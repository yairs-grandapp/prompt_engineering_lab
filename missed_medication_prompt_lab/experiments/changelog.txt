exp_002_more_scenarios                    [changes from exp_001_baseline]
------------------------------------------------------------------------
  Prompt template:  prompt_v0.txt   ->  prompt_v1.txt
  Temperature:      0.7             (unchanged)
  Inputs:           inputs_v0.json  ->  inputs_v1.json  (4 -> 20 scenarios, 5 per outcome)

  Prompt changes (v0 -> v1):
    1. Reworded the DID_TAKE clarification message: dropped the confusing
       "misunderstanding" phrasing -> warm "That's great to hear, thank you
       for letting me know! ... could you confirm you took today's
       medication..." wording.
    2. Restructured to mirror smart_conversation/prompt_v8:
         - Added SITUATION / YOUR TASK header and a POSSIBLE OUTCOMES block.
         - Grouped guidelines under [SAFETY] / [BEHAVIORAL] /
           [TONE AND COMMUNICATION] / [DOMAIN].
    3. Replaced the flat OUTCOME DETERMINATION list with TIERED OUTCOME RULES:
         - TIER 1: clear statement -> decide on the same turn.
         - TIER 2: unclear/confused -> one clarifying question, then
           COULD_NOT_VALIDATE.
         - TIER 3: silence ("<<NO RESPONSE>>") -> ask again, then
           COULD_NOT_VALIDATE on the 2nd silence.
    4. Added the @SYSTEM@ sensor system (adapted from v8's movement sensor):
         - Medication-box sensor may report the dose was taken.
         - "NEVER fabricate or assume sensor data" rule.
         - Defined the @SYSTEM@ message prefix in the general guidelines.

  Inputs change: expanded the test set from 4 to 20 scenarios (the original
  4 plus 16 new simple ones, 5 per outcome).

exp_003_refining_temperature        [changes from exp_002_more_scenarios]
------------------------------------------------------------------------
  Prompt template:  prompt_v1.txt   ->  prompt_v2.txt
  Temperature:      0.7             ->  0.4
  Inputs:           inputs_v1.json  (unchanged, 20 scenarios)

  Prompt changes (v1 -> v2):
    1. TIER 1 refusal now requires an explicit refusal to TAKE the medication
       ("I won't take it", "I'm not taking those pills").
    2. Carve-out: annoyance about being asked ("stop asking me about my
       pills", "leave me alone", "stop bothering me", "go away") is NOT a
       refusal -> do NOT return DID_NOT_TAKE_IT_AND_WILL_NOT_TAKE.
    3. TIER 2 updated to explicitly catch that annoyance/disengagement and
       route it to COULD_NOT_VALIDATE after one clarifying question.
    Fixes scenario_19 (upset senior was previously misclassified as a refusal).

  Temperature change: lowered 0.7 -> 0.4 for more consistent, less random
  outcome decisions.

exp_004_interpretation_fixes  [changes from exp_003_refining_temperature]
------------------------------------------------------------------------
  Prompt template:  prompt_v2.txt   ->  prompt_v3.txt
  Temperature:      0.4             (unchanged)
  Inputs:           inputs_v1.json  (unchanged, 20 scenarios)

  Prompt changes (v2 -> v3). Three correctness fixes found by auditing the
  exp_003 conversations themselves, not just the pass/fail labels:

    1. WILL_TAKE now requires an EXPLICIT commitment.
       A bare "I forgot" / "not yet" / "haven't taken it" no longer finalizes
       DID_NOT_TAKE_BUT_WILL_TAKE. The assistant stays conversation_in_progress,
       asks "Would you like to take it now?", and only decides after the reply.
       Fixes the FALSE POSITIVES in scenario_02 and scenario_11 (WILL_TAKE was
       returned even though the senior never committed to taking it).

    2. DID_TAKE clarification message and Reminder #2 reworded from questions
       into warm closing STATEMENTS.
       Previously they asked a question ("could you confirm...?" / "have you
       taken it now?") and then ended on the same turn, so the answer was never
       heard. As statements, finalizing same-turn is coherent.
       Fixes the dangling-question defect in scenario_01/05/06/07/08 (DID_TAKE)
       and scenario_09/10/12 (Reminder #2).

    3. TIER 2 tightened so a "who is this?" identity request plus the
       re-introduction counts as the single allowed clarifying turn.
       Fixes scenario_20 over-asking (it used 5 turns instead of the intended 3).

exp_005_followup_confirmation      [changes from exp_004_interpretation_fixes]
------------------------------------------------------------------------
  Prompt template:  prompt_v3.txt   ->  prompt_v4.txt
  Temperature:      0.4             (unchanged)
  Inputs:           inputs_v1.json  (unchanged)

  Prompt changes (v3 -> v4):
    1. DID_TAKE now waits for a follow-up. The clarification message is a
       QUESTION again; the assistant stays conversation_in_progress and returns
       DID_TAKE only after the senior confirms on the next turn. (Fixes
       scenario_01 — no longer asks and finalizes in the same breath.)
    2. Refusal now waits for a follow-up. Message #2 is delivered, the assistant
       stays in progress, and DID_NOT_TAKE_IT_AND_WILL_NOT_TAKE is returned only
       if the senior still refuses next turn. (Fixes scenario_03.)
    Maintained from v3: WILL_TAKE commitment carve-out, TIER 2 tightening,
    Reminder #2 as a statement.

  Known effect (scenarios intentionally unchanged): scenario_07 (DID_TAKE) and
  scenario_15 (refusal) have a single user turn, so the new follow-up hits
  silence and is expected to resolve to COULD_NOT_VALIDATE — i.e. those two will
  likely report FAIL until their scenarios gain a confirming second turn.

exp_007_no_capability_overclaims   [changes from exp_006_natural_clarifying_question]
------------------------------------------------------------------------
  Prompt template:  prompt_v5.txt   ->  prompt_v6.txt
  Temperature:      0.4             (unchanged)
  Inputs:           inputs_v1.json  (unchanged)

  Prompt changes (v5 -> v6):
    1. Added a [DOMAIN] guardrail against PRESENCE overclaims — Vega must not
       imply it can wait, stay on the line, watch, monitor, or confirm in real
       time. Bans lines like "I can wait while you do" (exp_006 scenario_02).
    2. Extended that guardrail to CONVERSATIONAL / counseling overclaims — Vega
       is not a counselor and the call ends after the reminder, so it must not
       invite the senior to "talk it through" or imply ongoing availability.
       Bans lines like "we can talk about it", "I'm here to support you".
    3. Reworded the scripted Message #2 (refusal) to remove the "please tell me
       your reasons, and we can talk about it calmly" invitation, so it no
       longer contradicts the guardrail.
    No outcome/flow logic changes.

exp_011_adaptive_messages          [changes from exp_010_validation_clarification]
------------------------------------------------------------------------
  Prompt template:  prompt_v8.txt   ->  prompt_v9.txt
  Temperature:      0.4             (unchanged)
  Inputs:           inputs_v2.json  (unchanged)

  Prompt changes (v8 -> v9). Driven by a line-by-line audit of the exp_010
  transcripts, which passed 20/20 but still leaked stylistic overclaims in the
  model-generated lines.

    1. De-scripted three of the four standard messages. The DID_TAKE
       clarification, the WILL_TAKE closing, and the refusal reconsider question
       are no longer fixed strings — they are now requirement-based guidelines
       that state what each response MUST accomplish and let Vega compose the
       wording adaptively. The COULD_NOT_VALIDATE soft message stays FIXED and
       word-for-word (it makes a factual promise about the SeniorMatics alert, so
       exact, auditable wording matters more than adaptiveness there).

    2. Removed two "recording" overclaims Vega cannot back up:
         - DID_TAKE clarification dropped "...everything is recorded properly on
           my end..." -> now framed only as making sure Vega understood correctly.
         - WILL_TAKE closing dropped "...and I'll make sure everything is noted."
       Vega does not write to any record; the sensors and backend do that
       separately.

    3. [DOMAIN] tightened with three guardrails:
         - Recording/logging: bans claiming Vega records, logs, notes, saves,
           updates, or files anything ("recorded properly on my end", "I'll make
           sure everything is noted", "I'll update your file", ...).
         - Joint/shared actions: bans "let's check your medication box together"
           and the like — Vega is not physically present. (exp_010 scenario_18.)
         - Extended the counseling/availability ban to also catch "I'm here to
           help you remember", "I'm here to gently remind you", and "whenever
           you're ready" (exp_010 scenario_02/03/11).

    4. TIER 3 first-silence re-check is now composed in Vega's own words rather
       than a fixed quote, consistent with the de-scripting above.

  No outcome/flow logic changes — the tiers, waits, and outcomes are identical to
  v8; only the wording policy (adaptive vs. fixed) and the [DOMAIN] guardrails
  changed.

  Prompt template:  prompt_v0.txt   ->  prompt_v1.txt
  Temperature:      0.7             (unchanged)
  Inputs:           inputs_v0.json  ->  inputs_v1.json  (4 -> 20 scenarios, 5 per outcome)

  Prompt changes (v0 -> v1):
    1. Reworded the DID_TAKE clarification message: dropped the confusing
       "misunderstanding" phrasing -> warm "That's great to hear, thank you
       for letting me know! ... could you confirm you took today's
       medication..." wording.
    2. Restructured to mirror smart_conversation/prompt_v8:
         - Added SITUATION / YOUR TASK header and a POSSIBLE OUTCOMES block.
         - Grouped guidelines under [SAFETY] / [BEHAVIORAL] /
           [TONE AND COMMUNICATION] / [DOMAIN].
    3. Replaced the flat OUTCOME DETERMINATION list with TIERED OUTCOME RULES:
         - TIER 1: clear statement -> decide on the same turn.
         - TIER 2: unclear/confused -> one clarifying question, then
           COULD_NOT_VALIDATE.
         - TIER 3: silence ("<<NO RESPONSE>>") -> ask again, then
           COULD_NOT_VALIDATE on the 2nd silence.
    4. Added the @SYSTEM@ sensor system (adapted from v8's movement sensor):
         - Medication-box sensor may report the dose was taken.
         - "NEVER fabricate or assume sensor data" rule.
         - Defined the @SYSTEM@ message prefix in the general guidelines.

  Inputs change: expanded the test set from 4 to 20 scenarios (the original
  4 plus 16 new simple ones, 5 per outcome).

  Prompt changes (v2 -> v3). Three correctness fixes found by auditing the
  exp_003 conversations themselves, not just the pass/fail labels:

    1. WILL_TAKE now requires an EXPLICIT commitment.
       A bare "I forgot" / "not yet" / "haven't taken it" no longer finalizes

       Fixes the dangling-question defect in scenario_01/05/06/07/08 (DID_TAKE)
       and scenario_09/10/12 (Reminder #2).

    3. TIER 2 tightened so a "who is this?" identity request plus the
       re-introduction counts as the single allowed clarifying turn.
       Fixes scenario_20 over-asking (it used 5 turns instead of the intended 3).

  Prompt changes (v8 -> v9). Driven by a line-by-line audit of the exp_010
  transcripts, which passed 20/20 but still leaked stylistic overclaims in the
  model-generated lines.

    1. De-scripted three of the four standard messages. The DID_TAKE
       clarification, the WILL_TAKE closing, and the refusal reconsider question
       are no longer fixed strings — they are now requirement-based guidelines
       that state what each response MUST accomplish and let Vega compose the

exp_013_discomfort_exception       [changes from exp_012_refining_messages]
------------------------------------------------------------------------
  Prompt template:  prompt_v10.txt  ->  prompt_v11.txt
  Temperature:      0.4             (unchanged)
  Inputs:           inputs_v2.json  (unchanged)

  Prompt changes (v10 -> v11). Behavioural change around uncomfortable seniors;
  the four outcomes themselves are unchanged.

    1. DISCOMFORT EXCEPTION (TIER 1). If the senior sounds annoyed, angry, or
       otherwise uncomfortable but has still given a clear answer (took it / will
       take it / refuses), Vega takes that answer at face value and finalizes on
       that turn — skipping the normal follow-up validation question (the DID_TAKE
       box-confirmation and the refusal reconsider question). The principle: once
       an uncomfortable senior has clearly answered, do not press them further.
       Calm seniors are unaffected — they still get the normal follow-up.

    2. New TIER 2B — upset/annoyed with NO clear answer. Pulled the upset/annoyed
       case out of TIER 2's one-clarifying-question flow. An upset or disengaged
       senior who has not said whether they took the medication (e.g. "leave me
       alone", "stop bothering me") now goes straight to COULD_NOT_VALIDATE — no
       clarifying question — which raises the caregiver alert. TIER 2 now covers
       only calm confusion / can't-remember / evasive (still one clarifying
       question). TIER 3 silence handling is unchanged.

    3. Refusal now announces the caregiver alert. The DID_NOT_TAKE_IT_AND_WILL_
       NOT_TAKE closing now tells the senior their caregiver will be notified to
       check in, matching the could-not-validate message. The reconsider question
       itself stays alert-free (still hoping they reconsider).

  Net effect: an uncomfortable senior is never badgered with a follow-up — if
  they answered, we take it; if they didn't, we validate and alert.

  BACKEND NOTE: the caregiver-alert promise now appears on BOTH
  DID_NOT_TAKE_IT_AND_WILL_NOT_TAKE and COULD_NOT_VALIDATE. Confirm the
  production system escalates on both outcomes.

exp_015_refusal_and_cnv_fixes      [changes from exp_014_commitment_guard]
------------------------------------------------------------------------
  Prompt template:  prompt_v12.txt  ->  prompt_v13.txt
  Temperature:      0.4             (unchanged)
  Inputs:           inputs_v2.json  (unchanged)

  Prompt changes (v12 -> v13). Two fixes from the exp_014 transcript review.

    1. Refusal taken at face value (scenario_13). A clear refusal is a definitive
       answer and no longer receives a reconsider/verifying question: the assistant
       finalizes DID_NOT_TAKE_IT_AND_WILL_NOT_TAKE immediately, with a respectful
       acknowledgement and the caregiver alert. The prompt now explicitly contrasts
       a settled refusal ("I WON'T take it") with "I haven't taken it / I forgot"
       (no decision stated), which still requires the follow-up before
       DID_NOT_TAKE_BUT_WILL_TAKE. Consequence: the reconsider question is removed
       from the flow entirely; the discomfort exception is narrowed to the DID_TAKE
       box-confirmation, and a stale routing note was corrected to TIER 2B.

    2. Hardened COULD_NOT_VALIDATE message (scenario_17). In exp_014 the model
       returned COULD_NOT_VALIDATE with self-authored text that (a) omitted the
       mandatory fixed soft message and its caregiver-alert promise, (b) ended on a
       question despite the conversation terminating, and (c) reintroduced a banned
       [DOMAIN] phrase ("I'm here to gently remind you"). The requirement now
       states the ENTIRE response must be the fixed soft message reproduced
       verbatim — nothing added, no question, no replacement wording.

  Effect: refusal scenarios (03, 13, 14, 15, 16) finalize in 2 turns; the terminal
  could-not-validate turn (17, 18, 19, 20) must be exactly the fixed message. Both
  are path-level behaviours not visible in the PASS/FAIL column — verify via the
  transcripts.

  Addresses the defects found in the exp_017 line-by-line review (97/100 label

  Prompt changes (v14 -> v15):
    1. Reluctance is not a refusal. Added an explicit rule that reluctance/mood

  validating) in some could-not-validate cases; outcome and alert are still

exp_019_ambiguous_opener_rule      [changes from exp_018_targeted_fixes]
------------------------------------------------------------------------
  Prompt template:  prompt_v15.txt  ->  prompt_v16.txt
  Runner:           src/conversation_runner.py (COULD_NOT_VALIDATE injection, unchanged)
  Temperature:      0.4             (unchanged)
  Inputs:           inputs_v3.json  (unchanged, 100 scenarios)

  Addresses the three fails and the re-introduction leaks found in the exp_018
  review. All three exp_018 fails shared one cause: an ambiguous first utterance
  was finalized as a terminal outcome instead of prompting a clarifying question.

  Prompt changes (v15 -> v16):
    1. RULE 0 (new, top of the tiered rules): do NOT finalize a terminal outcome
       on an ambiguous response. Finalize only when the meaning is unambiguous
       (clear took-it / explicit commitment / settled refusal / plainly confused
       or silent / explicit stop-signal). Ambiguous openers get exactly ONE
       clarifying/offer question, then classify from the reply. Names the specific
       openers that failed in exp_018: bargaining ("do I really have to?", "must
       I?" -> scenario_72), soft/reasoned declines ("I don't need them today" ->
       scenario_56), and vague frustration ("I'm done with all this" ->
       scenario_35).
    1b. TIER 2B tightened: immediate COULD_NOT_VALIDATE requires an EXPLICIT signal
       to stop/leave/go away; vague frustration is routed to RULE 0 (one clarifying
       question) rather than an immediate validate.
    2. Re-introduction sign-off ban: when re-introducing during confusion, state
       the role plainly ("I'm Vega, your care assistant") and ask the question, with
       no "here to gently remind you about your medication" attached. Targets the
       seven exp_018 clarifying-turn leaks (17, 20, 38, 41, 43, 51, 93).

  Not addressed: the plain "I'm here to support you"
  sign-off (probabilistic lexical ban, already reduced 9->3) and over-asking in
  some could-not-validate cases (cosmetic; outcome and alert correct).
